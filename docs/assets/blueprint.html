fhsystems · open-source blueprint · agentic-analytics

agentic-analytics: an AI analyst where every number traces back to a row.

Drop in whatever a business has: spreadsheets, PDFs, exports, emails. Get back a diagnosis of what happened, what went wrong, what the market says, and what to do next. Each claim links to the cell, page or URL it came from, and every figure is recomputed before the report ships.

self-hosted · one docker compose up API + MCP server + CLI Claude or local models via Ollama Apache-2.0
Numbers are computed, never guessedTables go into DuckDB and every figure comes from SQL the engine actually ran.
Every claim carries its sourceRow, cell, PDF page, email or URL. Click it and see the evidence.
Decisions, not summariesRanked actions with expected impact ranges, confidence and the check that proves them right or wrong.
01 · how one report is made

Watch a pile of files turn into a verified report

Three lanes run on purpose: tables are queried, documents are searched, the web adds outside context. An analyst agent plans across all three, and a separate verifier recomputes everything before anything leaves the engine.

ingest4 files in. sales-2026.xlsx has 2 sheets and 3 table regions; the merged header row is unpacked into columns month, revenue, orders, wholesale, refunds. price-list.pdf is 4 pages via Docling.
tables · sqlSELECT month, revenue, wholesale, revenue - wholesale AS retail, refunds FROM monthly ORDER BY month; → 6 rows, Jan–Jun 2026
docs · searchprice-list.pdf p.2, score 0.91: “Wholesale prices increase 12% from 15 March.” email-0412.eml, score 0.88: “we are pausing our standing order.”
web · contextindustry-benchmark.example: typical 2026 wholesale price rises for specialty roasters 5–8%. Marked external, never mixed with your numbers.
agent · planRevenue fell 7,900 in April. Decompose: wholesale −8,500, retail +600. Wholesale explains 108% of the drop. Check docs for a cause in March–April.
verifier14 numbers recomputed from SQL, 0 mismatches. 7 citations resolve to a row, page or URL. 1 claim downgraded to medium confidence (cause inferred from one email).
reportreport.json (schema v1) and report.html written. 2 findings, 2 recommendations, 1 open question for the owner.

03 · how a recommendation is earned

Six steps from a number to a decision you can defend

Most tools jump from “here is a chart” to generic advice. The engine walks a fixed ladder, and any recommendation that can't cite evidence from the rungs below it is dropped.

step 1MeasureKPIs per period, computed in SQL: revenue, margin, mix, rates.
step 2DetectChanges, breaks and anomalies against the business's own history.
step 3DecomposeSplit each change into its drivers: segment, product, client, price, volume.
step 4ExplainMatch drivers to events in documents and to outside benchmarks.
step 5DecideOptions ranked by expected impact, effort and risk, each with a range.
step 6CheckThe metric and date that will prove the call right or wrong.
recommendation R1 · from the example

Offer the hotel group a 6% volume tier to bring back the standing order

Wholesale is the whole April drop, and it lines up with the 12% rise. That rise was above the 5–8% the market moved, so a tier that lands near the market rate is the cheapest fix with the largest upside.

Evidence

Confidence
Medium. The cause rests on one email.
Next check

Across-the-board price cuts. Retail is growing and doesn't need them.
expected impact · monthly revenue
0+5,000+10,000

The range comes from recovering 50–90% of the lost 8,500, net of the 6% discount. Both inputs are shown in the report, so the owner can change them and see a new range.

open question for the owner

Did any other wholesale clients cut volume after 15 March? The data can't separate them yet.

04 · what others leave broken

The problems users complain about, and how this engine closes each one

Problem in today's toolsWhere it shows upWhat this engine does
Confidently wrong numbersChat analysts that do arithmetic in the model; reviews of AI data tools cite figures that were simply wrong.The model never computes. DuckDB runs the SQL, and a verifier recomputes every number in the report before it ships.
Spreadsheets treated as textMost RAG platforms chunk an Excel file like a document, so totals and trends are invented.Tables are detected and loaded as real tables, including merged headers and several tables on one sheet. Text gets search, numbers get SQL.
No way to check a claimAnswers arrive as prose with no source.Every claim carries a row, cell, page or URL, and the citation is clickable in the HTML report.
Advice with no basis“Consider improving marketing.”Recommendations must cite findings, carry an impact range and confidence, and name the check that will judge them.
Tables, documents and the web never meetText-to-SQL tools ignore documents; research agents ignore your numbers.One analysis joins all three lanes, and outside sources are always labelled as outside.
Business data leaves the buildingHosted tools upload files to a vendor; some consumer tiers train on them.Self-hosted by default, works fully offline with Ollama, no telemetry.
Hard to plug into a real systemChat UIs only.A typed JSON schema, an HTTP API, an MCP server and a CLI. The UI is optional.

    06 · what it's built from
    
A TypeScript engine with one small Python helper

    
It all ships as one compose file: the engine, a Docling parser, an optional SearXNG for web search and an optional Ollama for local models. No external database to run.

  

  

    
coreNode 22 · TypeScript · HonoEngine, HTTP API, job runner. pnpm monorepo.

    
modelsVercel AI SDKClaude by default; OpenAI or any Ollama model behind the same interface.

    
dataDuckDBSQL over tables plus full-text and vector search over text, in one embedded file.

    
parsingDocling sidecar · SheetJSPDFs, Word, scans via Docling; messy Excel via SheetJS and table-region detection.

    
webSearXNG · Brave · TavilyPluggable search. Self-hosted SearXNG by default, API keys optional.

    
contractZod → JSON SchemaOne schema validates the model's output and defines the API, MCP tools and HTML report.

    
doorsMCP SDK · CLI · grammYMCP server, terminal tool and Telegram bot on top of the same API.

    
proofVitest · eval datasetsSample businesses with known answers. Every release must keep 0 number mismatches.
