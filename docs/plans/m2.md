# M2 plan: Ingestion

Branch: `m2/ingestion`. Human gate: `no`.
Sources: docs/ROADMAP.md M2, docs/specs/ingestion-and-profiling.md §1–4, docs/specs/security.md §5, docs/specs/report-schema.md §2 (provenance shapes).

## Output contract (fixed here, consumed by M3)

`ingest(files, options) → IngestResult`:

- `files: FileRecord[]`: `{ id, name, sha256, mime, kind, size, status: "ingested" | "duplicate" | "rejected" | "failed", duplicate_of?, parent? }`.
- `tables: TableRegion[]`: `{ id, file_id, sheet?, hidden_sheet, range (A1), header_rows, columns: { name, letter, source_cells }[], rows: { row (sheet row number), cells: Cell[], is_total }[], transposed, notes: string[] }`. Cells keep `{ value, type, formula?, format? }`.
- `documents: DocumentSection[]`: `{ id, file_id, kind, page?, heading_path, char_start, char_end, text }`. Offsets are relative to the page text for PDFs and to the full document text otherwise.
- `documents_meta`: per document `{ file_id, kind, pages?, headers? (email) }`.
- `issues: IngestIssue[]`: `{ kind, severity, file_id, message, sheet?, cell?, range?, page? }`, where kind is one of `unreadable_file`, `password_protected`, `unsupported_type`, `archive_rejected`, `too_large`, `duplicate_file`, `missing_cached_value`, `needs_ocr`, `hidden_sheet`, `too_many_cells`.

Loading into DuckDB (`t_<id>`, `sources`) is M3's `packages/store` work. M2 fixes the in-memory shape that M3 loads.

## Tasks (in order)

1. **Intake.**
   - `sniff(bytes, nameHint)`: magic bytes; inspect ZIP entries for xlsx/docx; OLE for xls; `%PDF`; EML header heuristics; CSV/TSV delimiter sniffing; txt/md.
   - Limits: 50 files and 200 MB per job, 50 MB per file, 300 MB decompressed per ZIP (from the central directory), 2M cells per sheet.
   - sha256 via WebCrypto. Duplicates are ingested once.
   - Archives (`.zip`, `.7z`, `.rar`, `.gz`) are rejected with a clear message.
   - Every parse failure becomes an issue; nothing is fatal. Per-file timeout is 60 s.
2. **Grid read** (SheetJS): value, type, formula, number format, merged range; hidden sheets; formulas never evaluated; formula with no cached value → `missing_cached_value`.
3. **Region detection** (spec §3, steps 1–5):
   - Occupancy mask and connected regions with 1-row/1-column gap tolerance.
   - Split at fully empty rows/columns when both sides independently qualify as tables. This keeps side-by-side tables apart even though the gap tolerance would join them.
   - Scoring: ≥ 2 columns, ≥ 3 data rows, type consistency.
   - Header detection with title/note rows above. Multi-row merged headers → `Parent / Child`.
   - Unmerge by propagation.
   - Total rows by keyword plus sum check.
   - Transposed tables (months across columns) → long format.
4. **CSV/TSV** → grid → the same region pipeline.
5. **Documents:**
   - PDF via `unpdf`: text per page, one section per page. A PDF with no text layer → Docling if configured, else `needs_ocr`.
   - DOCX via `mammoth`: HTML → blocks, sections by heading. Text is the blocks joined with `\n`.
   - EML via `mailparser`: headers + body; attachments go back through intake with `parent`.
   - TXT/MD: sections by `#` headings or blank lines.
6. **Docling client:** `POST {DOCLING_URL}/v1/convert/file` (markdown out); fetch is injected; tested with a stub.
7. **Fixtures:**
   - `fixtures/xlsx/*.xlsx` (≥ 12, built by `fixtures/build.ts`) with hand-written `fixtures/xlsx/expected/*.json`.
   - `fixtures/docs/*` (pdf, docx, eml with attachment, scanned pdf, corrupted files).
8. Ledger, README, spec notes.

## Tests

- Intake:
  - sniffing table (each type, plus wrong extensions);
  - limits;
  - archive rejection;
  - duplicates;
  - a corrupted xlsx/pdf/docx → `unreadable_file` issue, no throw;
  - timeouts.
- Regions: every `fixtures/xlsx` file matches its expected JSON exactly (headers, ranges, row numbers, totals, transposition).
- Documents:
  - the PDF yields per-page sections with offsets that slice to the right text;
  - DOCX headings map to sections;
  - the EML gives headers + body + attachment re-intake;
  - the scanned PDF → `needs_ocr`;
  - the Docling stub path.
- Golden dataset: coffee-roaster-v1 ingests into 3 table regions (Orders, Monthly summary, costs) and 3 documents. The M1 fixture's quote spans (page 2, email body, ops-notes §3) match the extracted text.

## Acceptance → proof

| Criterion | Proof |
|---|---|
| All xlsx fixtures match the expected tables | `bunx vitest run packages/ingest` (fixture-driven test) + `bun run --filter @agentic-analytics/ingest demo fixtures/xlsx` |
| Mixed PDF, DOCX and EML produce sections with page and offset | ingest demo over `fixtures/docs` + coffee-roaster-v1, printing sections |
| A corrupted file yields a `QualityIssue`, not a crash | corrupted fixtures in the demo + tests |

## Risks

- pdf.js text extraction may not reproduce the authored line structure, so M1 fixture offsets could drift. A test compares them; if they differ, re-base the fixture builder on extracted text and record the change.
- Region heuristics are fiddly. The expected JSONs are the contract, so keep them small and hand-checked.
- Worker-thread isolation (security §5) needs a Node adapter and a compiled worker entry. M2 ships in-process timeouts; true isolation is recorded as a known gap.
