# M12 plan: Docs site and launch (human gate)

M12 is a human gate. The agent builds and checks everything reviewable, opens the PR, sets the milestone to AWAITING_REVIEW, and stops. The maintainer performs the irreversible or public steps after review, following `docs/LAUNCH.md`:

- making the repo public;
- tagging v0.1.0 (which builds the GHCR image);
- enabling GitHub Pages;
- posting the launch.

## Tasks

1. **`examples/coffee-roaster`:** the demo input, copied from `evals/datasets/coffee-roaster-v1/files`. A check keeps the copies byte-identical.
2. **`scripts/readme-assets`** (`bun run readme:assets`, `readme:check`, `readme:check:browser`):
   - `hero.ts`: animated SVG, light and dark, static under reduced motion, with no scripts and no external references, under 100 KB;
   - `mermaid.ts`: `docs/assets/diagrams/{architecture,pipeline}.mmd` injected between markers in README.md and ARCHITECTURE.md;
   - `tables.ts`: `problems.yaml` (7 blueprint problems plus the wrong-metric and injection rows, each with its source) and the eval table from `evals/results`. Real-model rows show only when they exist; the baseline is never shown as model quality;
   - `check.ts`: drift (byte for byte), hero rules, and the GIF (exists, under 5 MB, ≤ 30 s, a clean `.tape`);
   - browser checks (Playwright): hero animations under reduced motion and without it, the `<picture>` variant per scheme, and the citation click on the example report;
   - `demo.sh`: VHS records `demo.tape` (`aa analyze examples/coffee-roaster --open`, scripted model), Playwright records the report clip with a citation click, and ffmpeg joins them into `demo.gif`.
3. **README:** rewritten around the visuals, with a quickstart that matches the shipped commands.
4. **`apps/docs`:** Astro Starlight with every section in DOCS-SITE §1:
   - interactive islands: `Pipeline`, `CitationDemo`, `Decomposition`, `RagStepper`, `VerifierDiff`;
   - Mermaid from the shared `.mmd` files;
   - reference pages generated from the OpenAPI spec and the JSON Schemas.
5. **Workflows:**
   - CI gets the `readme-browser` job;
   - `docs.yml` builds the site on PRs and deploys to Pages from main (it takes effect once Pages is enabled);
   - `release.yml` builds and pushes the GHCR image and the GitHub release on a `v*` tag.
6. **Release:** CHANGELOG.md, the v0.1.0 release notes, `docs/LAUNCH.md` (checklist and post drafts), SECURITY.md, CONTRIBUTING.md.
7. **Fresh-machine run:** a clean clone, following only the docs, run by QA and timed.
8. **STATE:** AWAITING_REVIEW, the open public steps, and the gaps.

## Risks

- VHS needs `ttyd` and `ffmpeg`; it is installed with `brew install vhs`, as a dev tool only (D15).
- The default embedder (bge-m3) is a large download. The docs quickstart shows `--embedder hash` for a fast first run, and the real embedder as the quality setting.
- Pages and GHCR need the repo public, or the maintainer's settings, so they are verified after the human step.
