# M13k: hero restructure (hex.tech's structure) and a self-demonstrating exhibit

Maintainer instruction (2026-10-19): follow hex.tech's structure, not just its style.

- A centred statement block on top: eyebrow, serif headline, one or two plain lines on what it is and what it solves, actions, the install line. No two-column hero.
- The report exhibit below it, full container width, as its own framed section.
- Self-demonstrating, no hover needed: as it scrolls into view the numbers verify one by one, then a guided walkthrough steps through 3–4 key facts, opening each margin note (SQL + source rows) with a step indicator. Scroll drives the steps (sticky on desktop), with replay and prev/next. Hover and focus still explore.
- Reduced motion / no JS: all steps as a static ruled list. Mobile: the same walkthrough stacked, notes below the figure.
- Lighthouse ≥ 95, axe clean, no layout shift, light only.

## Tasks

1. `walkthrough()` (apps/docs/scripts/landing-data.ts): the steps chosen from the run's data by role, never by typed id:
   1. the headline change;
   2. its current-period SQL input (SQL + cited rows);
   3. the driver's contribution and share;
   4. the quoted document.

   Written into exhibit.json.
2. `ExhibitNote.astro`: the note body, shared by the margin column and the static list.
3. `Exhibit.astro`: the step bar (caption, progress rule, ←, →, Replay), the sticky section and its track, and the static list. The script:
   - runs the verification on view;
   - maps scroll to steps on desktop;
   - runs a timer on small screens while the notes are on screen;
   - keeps hover, focus and pin.

   An inline pre-paint script sets `data-walk="live"` only without reduced motion, so there is no layout shift.
4. index.astro: the statement block and the exhibit sheet.
5. DESIGN.md §2/§4/§6/§7, DOCS-SITE.md, STATE.
6. Screenshots of each step (desktop, mobile) and the recording (`site-screenshots.ts`).

## Tests

- **Unit:** the walkthrough's steps by role against the recorded run, with no typed digits.
- **Browser:**
  - the verification runs on view;
  - desktop scroll steps, each opening its note, with the section on screen, and prev/next/replay;
  - mobile timed steps, notes below the figure, the sticky bar, no shift when stepping, manual stepping stops the timer;
  - a static list under reduced motion;
  - a static list without JS;
  - no box moves while the fonts arrive late;
  - axe and 360 px overflow (existing).
- **Lighthouse** on `/` and on a Learn page.

## Risks

- **Scroll-jacking feel:** steps follow native scroll; nothing captures the wheel.
- **Tall notes in a sticky section:** the section is centred with a 41rem extent, and scroll mode only applies from 1100 × 704 px (review round 1: between 900 and 1100 px the narrower notes column made the SQL note too tall); a browser test checks every note fits at 1100 × 704.
- **CLS from timed steps on mobile:** every note shares one grid cell as tall as the tallest, and the captions do the same.
