# M13d: standalone CLI binaries

Maintainer's request (2026-10-16): attach standalone `aa` binaries (linux-x64, linux-arm64, macos-arm64, windows-x64) built with `bun build --compile` to v* releases, with SHA256 checksums; first verify DuckDB's native module works in a compiled binary (else document it and keep Docker as the install path); test the workflow on `v0.1.0-rc.1`, then delete it.

## Tasks
1. Probe DuckDB in a compiled binary (it fails: libduckdb isn't embedded) → embed the library, stage it to a cache folder, preload it via `bun:ffi` (`apps/cli/src/native-lib.ts`, `scripts/build-binary.ts`).
2. Make the CLI bundle-safe: inline prompts (`prompts.gen.ts` + `prompts:check`), binary-specific defaults in `apps/cli/src/standalone.ts` (hash embedder, no viewer, eval results dir, doctor runtime).
3. `binaries.yml` (native runner per target, smoke test: doctor + offline eval) called by `release.yml`; pre-release tags never `latest`.
4. Docs: README, quickstart (per-platform checksums), CLI README, D16, STATE.
5. Reviews, then the rc tag test and cleanup.

## Risks
macOS/Windows library preload (verified in CI), Windows DLL replace races (handled), binary size (~140–200 MB), no ONNX in the binary (documented).
