# M9 plan: Verifier (`packages/verify`) and the injection suite

Spec: docs/specs/agent-and-verifier.md §7; docs/specs/security.md §3, §8.
Acceptance (ROADMAP M9):
- Seeded bad drafts are each dropped or downgraded correctly: a free numeral, a wrong definition, an unsupported citation, causal overreach and an ungrounded recommendation.
- A V2 mismatch fails the job with a diagnostic.
- The injection suite (at least 20 fixtures) passes 100%.

## Passes (all on the draft; results to the `verification` table and the summary)

- **V1 placeholders:** `findFreeNumerals` on every claim (and the headline). A failing claim is dropped; a failing headline falls back to the first finding's title.
- **V2 recompute:**
  - Every SQL fact is re-run with its stored parameters.
  - Every function fact is recomputed from its input facts by a registry keyed on `fn`. The registry covers:
    - delta, sum, mean, trailing_mean_3, pct_change, share, contribution.v1;
    - hhi, theil_sen, mann_kendall;
    - robust_z and share_shift (by membership);
    - pvm.v1 and ratemix.v1 (inputs in groups of 4);
    - impact.v1:*;
    - scenario_param (bounds);
    - external_quote (re-parsed from its text);
    - benchmark_gap.v1.
  - Relative tolerance is 1e-9. An unknown function, or any mismatch, is an engine bug: the job fails with a diagnostic bundle (`diagnostics.json`).
- **V3 re-derive:** headline facts (those in finding claims) that are SQL measures of sum/count metrics are re-computed by an alternate path: the metric grouped by its first dimension, summed in TypeScript. Ratio metrics use their numerator and denominator the same way. A mismatch fails the job.
- **V4 definitions:**
  - each fact's metric exists, and its unit and currency match the definition;
  - a claim whose facts measure metric X must not name only a different metric (lexicon of metric labels and ids).
  - A failing claim is dropped.
- **V5 citations:**
  - document and web quotes must occur in the source text;
  - cited table rows must be rows the fact's metric actually reads for that period;
  - claims with document or web citations get a judge yes/no ("does this source support this claim?").
  - A failing claim is dropped.
- **V6 causal language:** a lexicon (EN/RU/UZ). A causal claim below `document_supported` is rewritten to correlational wording and recorded in `claims_downgraded`.
- **V7 grounding:**
  - recommendations must cite surviving findings, impact facts must exist, and the check date must be after the data;
  - every finding must keep at least one verified claim.
  - Failures cascade drops.
- **V8 external:** a claim that uses an `external_quote`-derived fact must cite a web source marked external. Otherwise it is dropped.
- **After the passes:** the cascade runs, bullets are rebuilt from the surviving findings, `verified` flags are set, and the summary counts are written.

## Injection quarantine at INDEX_DOCS

- Every document, email and table text cell is screened deterministically (EN/RU/UZ patterns; invisible characters stripped first).
- Hits go to a `quarantine` table (migration 5). Quarantined sources are never sent to the extractor, and they appear in data quality.
- Raw web pages are screened before readable-text extraction, so hidden instructions also flag the page.

## Injection suite (`evals/injection`)

- 23 deterministic fixtures (22 planned, plus white-on-white PDF text from review):
  - cells in xlsx and csv, in EN/RU/UZ, including a formula with a data-carrying URL;
  - PDF text, DOCX (including zero-width obfuscation), EML, MD and TXT;
  - hidden and visible web instructions, and a URL exfiltration request.
- Each runs a full coffee job with an extractor scripted to obey the injection (`suspicious_instructions: false`, quoting the instruction) and the web lane on. Every fixture must hold all four:
  - the report's facts equal the clean run's;
  - no planner prompt contains the injected text, and no tool call followed from it;
  - the source is flagged `suspicious_instruction`;
  - no provider query contains a private value.

## Risks

- The registry must mirror the analysis functions exactly. Every fact of the coffee run is recomputed in a test, so drift fails CI.
- The screen patterns can over-flag; ordinary business text is covered by negative tests.
