# M13i: Website v2 ("the audited page")

Spec: `docs/design/website-v2.md` (the maintainer's design spec, merged into `apps/docs/DESIGN.md` by this PR and then
deleted). Everything v2 doesn't change in DESIGN.md stays.

## Tasks, in order

1. **Light only.**
   - Remove the dark tokens, `prefers-color-scheme: dark` rules, the theme toggle (`ThemeToggle.astro`) and the `starlight-theme` handling.
   - Starlight's `ThemeProvider` and `ThemeSelect` are overridden: always `data-theme="light"`, no control.
   - Code blocks use `github-light` only.
   - Mermaid, the islands and the pipeline scene drop their dark branches on the site. The README GIF keeps its own dark variant; it is not the site.
2. **v2 tokens and type.**
   - The neutral palette (page `#f8f8f6`, grid `#ecece8`, …) goes in `tokens.css`.
   - Docs/Learn prose uses Source Serif 4 text at 1.0625rem / 1.65.
   - Labels are mono uppercase at +0.08em.
3. **Landing page** (`src/pages/index.astro`), sections exactly as spec §6:
   - **Frame:** one long frame with 1px rules on the 1180px container and `+` ticks where the section hairlines meet it.
   - **Graph paper:** behind the hero and section headers only, faded with a CSS mask.
   - **Status strip:** generated (`statusStrip()` in `scripts/landing-data.ts`, from `evals.json`, `pipeline.json`, package.json and the test sources).
   - **Hero exhibit:** server-rendered in its final verified state. A small script replays the verification once, only without reduced motion, ≤ 2.5 s. Margin notes open on hover/focus (Esc/blur closes them); chips link to an on-page fact ledger without JS.
   - **§1–§4 and the footer.**
4. **Exhibit data** (`exhibitData()` in `scripts/landing-data.ts`), from the same recorded run as the hero animation:
   - the report's own claims and recommendation;
   - each fact's SQL split into lines and its parameters, or its function and inputs;
   - the cited sheet rows read back from the run's DuckDB (`_row`), with the cited row marked.
5. **Docs/Learn layout.**
   - Overrides of `TwoColumnContent` and `PageSidebar`, giving the columns sidebar 240px | article 64ch | margin ~260px.
   - The TOC sits sticky at the top of the margin and collapses under 1200px (Starlight's mobile TOC).
   - Serif reading body; h2 without a rule; h3 in Plex Sans 600.
6. **`<Sidenote>`** (`src/components/learn/Sidenote.astro`):
   - numbered with CSS counters and floated into the margin;
   - under 1000px a tap-to-expand inline note (checkbox + label, so it works without JS);
   - also a `<MarginNote>` (unnumbered) and a `.aa-fullwidth` figure class.
   - Learn pages use them for fact IDs, sources, glossary terms and caveats.
7. **Epigraph** (`epigraph` frontmatter, Learn stage pages): one serif-italic sentence on the problem the stage solves, rendered by `PageTitle`.
8. **Tests.**
   - `scripts/test/landing-exhibit.test.ts`: every exhibit/status figure is a fact value or a generated count; the exhibit's rows are the cited rows.
   - `scripts/test/site-light.test.ts`: no dark tokens, toggle or media queries in the site sources.
   - Browser (`scripts/site/browser/site.spec.ts`): light only; the hero sequence (and none under reduced motion); a margin note opens on hover and focus, Esc closes it; sidenotes in the margin at 1440 and inline under 1000; no scroll at 360; axe.
9. **Screenshots and recording.**
   - `site-screenshots.ts`: landing and a Learn page at 1440 and 390, plus a webm/GIF of the hero sequence and a margin note opening.
   - Lighthouse on `/` and a Learn page.
10. **DESIGN.md** merged with v2; the v2 file deleted (it was never committed). STATE and the docs README updated.

## Risks

- **Sidenotes vs. the sticky TOC.** Both live in the margin column. The TOC has the page background and a height cap, and notes scroll beneath it.
- **Status strip test count.** Vitest's own count needs a full run, too heavy for every `generate` (typecheck runs it). The strip shows the exact number of test files from vitest's include globs instead (recorded under "Decisions made by agents").
- **Lighthouse** isn't a repo dependency: it runs once through `bunx lighthouse` against the preview, and the scores go in the PR.
