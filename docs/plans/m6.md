# M6 plan: Retrieval (`packages/retrieval`)

Spec: docs/specs/retrieval.md. Acceptance (ROADMAP M6): recall@8 ≥ 0.85 on the coffee-roaster and printing-shop corpora; works with the reranker missing (degraded flag).

## Tasks (in order)

1. **Chunker** (`src/chunk.ts`, pure): document/email sections from the workspace `sources` table → chunks of 300–600 tokens (token estimate: words × 1.3), 15% overlap, split on paragraphs then sentences, never inside a table (pipe/tab-separated lines kept together; an oversize table is its own chunk). Each chunk: `source_id`, `page`, `char_start`/`char_end` into the page/document text, heading path, cleaned text, and a contextual prefix `[file · section path · date]` (emails: sender, recipient, date).
2. **Embedders** (`src/embed.ts`): `Embedder` interface (`id`, `embed(texts, "query" | "passage")`). `transformersEmbedder` runs `@huggingface/transformers` in-process (default `Xenova/bge-m3`; `Xenova/multilingual-e5-small` as the small CPU option), loaded lazily. `hashEmbedder` is deterministic (hashed character n-grams): used by tests and as the offline fallback, never needs a download.
3. **Indexes** (`src/index-job.ts`, SQL in `src/retrieval.sql.ts`): write chunks with embeddings to `chunks`; build the DuckDB `fts` BM25 index on `prefix || text` with the stemmer for the corpus language (english / russian / none for Uzbek and mixed).
4. **Search** (`src/search.ts`): BM25 top 50 + exact vector top 50 (`list_cosine_similarity`), RRF k = 60, top 30 to the reranker, keep 8. With no reranker (or if it fails to load): fused order, `degraded: ["rerank"]`. Filters: source ids, date range.
5. **Reranker** (`src/rerank.ts`): `Reranker` interface; `transformersReranker` (cross-encoder, default `Xenova/bge-reranker-base`, bge-reranker-v2-m3 when an ONNX export is available).
6. **Citations** (`src/cite.ts`): `quoteFor(chunk, start, end)` returns an exact substring of the source span, ≤ 300 chars, with its offsets.
7. **Corpora + eval**: a deterministic printing-shop document corpus (English + Russian PDFs, DOCX, emails) in `evals/datasets`, labelled retrieval questions for both corpora in `evals/retrieval/`, and `bun run eval:retrieval` reporting recall@8, MRR and answer-in-context per embedder/reranker setting.

## Tests

- Chunker: hand-built sections → exact chunk boundaries, overlap, table kept whole, offsets map back to the exact source text.
- RRF: hand-computed fused scores.
- Search integration on an in-memory workspace with `hashEmbedder` and a scripted fake reranker: filters, the degraded flag, rerank order.
- Recall test (unit, offline): hashEmbedder + BM25 on both corpora, recall@8 ≥ 0.85 asserted.
- Quote helper: exact substring, 300-char cap.

## Risks

- Model downloads (hundreds of MB) may be slow or blocked: tests never need them; the real-model eval is a separate command, DEFERRED if the download fails.
- The `fts` extension downloads on first `INSTALL`; CI has network. The index is static, so it is rebuilt after chunks are written.
- `chunks.embedding` is `FLOAT[]` (variable length) in migration 1, so search uses `list_cosine_similarity`; the dimension follows the model.
