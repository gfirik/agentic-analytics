# M13f plan: product website (landing page + themed docs)

Spec: the maintainer's item 6 (website redesign) and its follow-up (a cool palette clearly different from pas-agent); docs/DOCS-SITE.md.

Acceptance:

- `apps/docs/DESIGN.md` first: "an AI analyst you can audit". Tokens live in one CSS file and agree with the doc.
- A custom landing page replaces the Starlight splash:
  - the hero carries the one-liner and the pipeline animation (the README GIF scene);
  - the coffee-roaster report with clickable fact IDs;
  - the real-data demo (Online Retail II);
  - "why it's different";
  - real eval numbers with honest caveats;
  - quickstart and binary downloads;
  - the four doors.
- Every docs page keeps its content but is fully on-system: header, sidebar, TOC, code blocks, diagrams and islands. Navigation and section intros are tightened.
- A footer on every page says "Built by fhsystems" and links to https://fhsystems.dev.
- favicon.svg and favicon.ico, an OG image, a sitemap that includes the landing page, and a custom 404.
- Self-hosted fonts and no third-party requests at runtime. WCAG AA in light and dark, no horizontal scroll at 360 px, a reduced-motion fallback, and the page is complete without JS.
- Every command shown exists in the CLI (a test checks it).
- The Pages workflow stays skip-while-private.

## Tasks, in order

1. **DESIGN.md and tokens.**
   - `src/styles/tokens.css` holds the palette, type, spacing and motion, for light and dark.
   - It works with no JS (`prefers-color-scheme`) and with Starlight's `data-theme`.
2. **Shared chrome.**
   - `SiteHeader` / `SiteFooter` / `ThemeToggle` / `BaseLayout` for the landing page and the 404.
   - Starlight overrides (`Header`, `Footer`, `ThemeSelect`, `PageTitle`) reuse them, so the theme choice is shared through Starlight's own `starlight-theme` key.
3. **Starlight theming.**
   - `--sl-*` variables are mapped to the tokens.
   - Expressive Code themes are re-based onto the token surfaces, so its contrast correction still applies.
   - Sidebar, TOC, tables, asides, pagination and search are restyled.
   - Mermaid and the islands use the tokens.
4. **Generated landing data** (`scripts/generate.ts`):
   - `landing.json`: finding F1 of the real coffee-roaster run, the facts it uses with their computations and citations, and the verifier summary.
   - `evals.json`: the suite metrics are computed by the eval runner's own `summarize()` from `evals/results/*.json`, and the real-data checks are read from the latest `*-baseline-real.json`.
   - No number is typed by hand.
5. **Landing page** (`src/pages/index.astro`) with a `LedgerReport` island. Fact chips are anchors into a static fact ledger, so the page works without JS.
6. **Site files:**
   - `public/favicon.svg` and `favicon.ico`;
   - `public/og.png`, rendered by `scripts/site/og.ts` (Playwright) from an on-system HTML card;
   - `sitemap.xml` (an index that points at Starlight's sitemap);
   - a custom 404 (`disable404Route`).
7. **Docs navigation.**
   - Reorder and relabel the sections.
   - Write short section intros.
   - Leave room for the later "Learn" section, between "How it works" and "Use it".
8. **Checks:**
   - a vitest test that every `aa …` / `bun run …` command in the site sources exists;
   - a Playwright site job (CI) that checks:
     - no non-localhost requests;
     - axe WCAG 2 AA in light and dark on the landing page, a docs page and the 404;
     - no overflow at 360 px;
     - favicon, OG image and sitemap.
9. **Screenshots** in `docs/assets/site/`: the landing page and a docs page, light and dark, desktop and mobile, plus a side-by-side with pas-agent.
10. **Records:** docs/DOCS-SITE.md, apps/docs/README.md and STATE.md.

## Risks

- The Starlight internals change between minors. We override only public component slots and pin `@astrojs/starlight` ^0.36.
- Changing `pipeline-scene.ts` would force re-recording the README GIFs (hash check). The site re-themes the scene through its CSS custom properties instead, so the scene file is untouched.
- The axe colour checks depend on Expressive Code's token colours. Its `minSyntaxHighlightingColorContrast` is applied against our re-based backgrounds.
