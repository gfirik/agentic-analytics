# M1 plan: Contracts and golden fixtures

Branch: `m1/contracts-fixtures`. Human gate: `notify` (merge and continue, notify the maintainer).
Sources: docs/ROADMAP.md M1, docs/specs/report-schema.md, docs/specs/metric-layer.md §1, docs/specs/models.md, docs/specs/analysis-library.md §4–5 (numbers behind the fixture), docs/EVALS.md §1, docs/assets/blueprint.html §02.

## Tasks (in order)

1. **`packages/schema`** (Zod 4):
   - `report.ts`: report v1 exactly per report-schema.md §1–5, plus an additive optional `evidence` block (source excerpts the HTML needs to show cited rows/passages offline; see Decisions).
   - `integrity.ts`: cross-reference checks Zod can't express: every `{{N…}}` placeholder and every `facts[]`/fact-id field points at an existing fact, every citation `source_id` exists, `because` finding ids exist, assumption ids exist, no free numerals in claim text (dates allowed), `summary.bullets` ≤ 5.
   - `metric.ts`: metric YAML (metric-layer.md §1) incl. ratio numerator/denominator.
   - `config.ts`: `agentic-analytics.config.yaml` (models.md §4).
   - `events.ts`: job events (interfaces.md §1 SSE event names, ARCHITECTURE §2 stages).
   - Register all four in `jsonSchemaRegistry` → committed `packages/schema/json/*.schema.json`; drift check guards them.
2. **Fixture** `packages/schema/test/fixtures/report.coffee-roaster.json`: the full blueprint story (F1 wholesale regression, F2 refund rate, F3 retail growth, R1 volume tier, open question, assumptions, data quality, sources, evidence). Every number is a fact. Values are produced by `evals/datasets/coffee-roaster-v1/build.ts` math helpers and checked by a test that recomputes them from the dataset's monthly table (no hand-typed derived numbers).
3. **`evals/datasets/coffee-roaster-v1`** (hand-built, deterministic `build.ts`): `sales-2026.xlsx` (Orders sheet with transactions that aggregate exactly to the blueprint monthly table, Monthly sheet with a merged-header summary + a Costs region with a planted ×1000 typo; dd/mm text dates for the ambiguity; "OOO Hotel Group" / "Hotel Group LLC" spellings), `price-list.pdf`, `email-0412.eml`, `ops-notes.docx`, `answers.yaml`. A test asserts the built files' aggregates equal `answers.yaml`.
4. **`packages/models`**: `ModelClient` interface (models.md §2), own `Message`/`ToolSet`/`Step`/`Usage` types, `FakeModel` (`packages/models/testing` export; scripted by role + prompt hash/substring), providers `ollama` and `openai-compatible` over `ai` + `@ai-sdk/openai-compatible` with explicit base URLs (never the default gateway), config resolution from env/config (`PLANNER_MODEL=ollama:qwen3.5:9b`), structured-output retry with validation feedback (§5), timeouts.
5. **`packages/report`**: React SSR (`react-dom/server`) → one self-contained HTML (inline CSS + JS, no external requests), section order per report-schema §6, clickable numbers (computation panel), clickable citations (rows/cells highlight, doc quote + page, web with External badge), light/dark, keyboard, print CSS. Script `render:fixture` writes `packages/report/out/report.coffee-roaster.html`.
6. **`aa doctor`**: after provider checks, call the configured planner model with a one-line prompt when a provider is reachable; otherwise print "skipped".
7. Ledger, READMEs, spec updates.

## Tests

- schema: fixture validates (Zod + integrity); targeted invalid reports fail (missing fact, unknown source, free numeral, >5 bullets, bad enum); metric YAML samples from the spec parse; config sample parses.
- dataset: built xlsx re-read with SheetJS aggregates to the monthly table; fixture facts recompute exactly (hand arithmetic in comments: 36,200/44,100 − 1 = −17.9%; −8,500/−7,900 = 107.6%; refunds 1.2% → 3.4%).
- models: FakeModel sample test (generateObject + generateWithTools + embed); retry-with-feedback on invalid object; openai-compatible provider exercised with an injected stub `fetch` (no network); config parsing.
- report: SSR of fixture → no `http(s)://` in `src=`/`href=` of scripts/styles/images, every placeholder substituted, required section order; happy-dom runs the inline script and a citation click highlights the cited rows; number click opens its computation.
- cli: doctor model ping uses the injected client; skipped when nothing reachable.

## Acceptance → proof

| Criterion | Proof |
|---|---|
| The fixture validates | `bun run test packages/schema` + `bun run --filter @agentic-analytics/schema validate:fixture` |
| `render:fixture` produces offline HTML with working citation highlight | `bun run --filter @agentic-analytics/report render:fixture` + the happy-dom test |
| `FakeModel` used in a sample test | `packages/models/test/fake-model.test.ts` |
| `aa doctor` can call the configured model with a one-line prompt | Unit test with stub; real call DEFERRED (no model configured): `OLLAMA_BASE_URL=… bun run aa doctor` |

## Risks

- AI SDK v7 API differences (generateObject vs output objects): wrap tightly, test with stub fetch.
- SheetJS must come from the official CDN tarball (AGENTS.md §3).
- Fixture numbers must be computed, not typed: a test recomputes them.
- Blueprint figures that aren't spec'd as golden ("about 810", "4,000–7,500") are illustrative; the fixture uses `impact.v1` formulas and records the computed values.
