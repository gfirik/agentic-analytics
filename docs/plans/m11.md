# M11 plan: Evals at scale

Acceptance (ROADMAP M11):
1. The full suite runs locally with one command (`bun run eval -- --suite full --model baseline`).
2. The full harness runs end to end with FakeModel: the `baseline` scripted model, the full suite, and the smoke suite in CI.
3. Real-model results are published for every configured free/local model. None is configured here, so this is DEFERRED with commands.
4. The default model is chosen from results once they exist. DEFERRED: it needs a real-model result.

## Tasks

1. **`evals/generator`:**
   - 10 archetypes × 3 variants;
   - planted events: key client loss, supplier switch → refunds, cannibalization;
   - distractors: noise blip, seasonal peak, coincidental and irrelevant documents;
   - quality issues: ×1000 typo, date ambiguity;
   - seeded PRNG, a SHA-256 manifest, versioned answer keys.
2. **`evals/runner`:**
   - the baseline scripted model (dataset-agnostic);
   - scoring by finding subject (EVALS §2 metrics and bars);
   - `runSuite`, results JSON, RESULTS.md;
   - `aa eval`.
3. **CI smoke suite:** 3 datasets, as a vitest test in the normal check.
4. **Fix what the suite finds:** RENDER under tsx, V1 member names in decomposition labels, ranking slots per metric family.
5. **Docs:** EVALS.md, READMEs, analysis spec §6, STATE.

## Tests

- **Generator:** 30 unique datasets; byte-identical to the manifest; answer keys equal to the versioned YAML; planted facts recomputed from the orders (the key client stops, refunds rise); the typo at the named cell; every variant ingests.
- **Scoring:** hand-built reports covering subject, matching windows, driver, cause, action, distractor, quality and the bar arithmetic.
- **Smoke:** completion, 0 mismatches, adherence, grounding, and P1 found with its driver in all 3 datasets.

## Risks

- The engine misses some planted events. Results are shown, not hidden (EVALS §4), and the gaps are recorded.
- The baseline is not a model, and RESULTS.md says so.
