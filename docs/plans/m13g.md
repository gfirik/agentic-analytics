# M13g plan: Learn section (concept guides + tutorials)

Spec: the maintainer's item 9 ("Learn" = concept guides and tutorials for a smart beginner, on the coffee-roaster example end to end) and docs/DOCS-SITE.md. Design: apps/docs/DESIGN.md.

Acceptance:

- `learn/` in the docs, between "How it works" and "Use it":
  - `learn/index`: the big-picture overview, a diagram linking every stage;
  - `learn/stages/*`: ten stage guides (ingestion & profiling, metric layer, analysis, retrieval, web lane, agent/planner, verifier, report & fact IDs, model router & free providers, security);
  - `learn/tutorials/*`: five tutorials (first file, confirm metrics, documents and emails as evidence, Claude via MCP, evals on your own data);
  - `learn/glossary`.
- Each stage guide: the problem it solves, an interactive diagram with the real coffee numbers going in and out, links to the repo files, a "try it" command, the AI/ML concepts behind it in plain words, and further reading.
- Every number, fact id, SQL snippet, quote, score, verifier result, call-log record and terminal transcript comes from real engine output, generated by a script and drift-checked by a test.
- Every command shown exists; every repo link points at a file in the checkout.
- DESIGN.md checklist on every page: axe AA light and dark, no horizontal scroll at 360 px, complete without JS and with reduced motion, no third-party requests, green only for "verified".

## Split with "How it works"

How it works stays the reference (what each stage does, exactly). Learn is the beginner path: why the stage exists, what goes in and out on the example, and the ideas behind it. Each Learn page links "Go deeper" to its How it works page and reuses its islands where they fit (RagStepper, VerifierDiff, Decomposition, CitationDemo, Mermaid) instead of copying text.

## Data

- `apps/docs/scripts/learn-data.ts` records everything the pages show and writes `docs/assets/learn/learn.json` (checked in, like `pipeline.json`):
  - one web-enabled run of `examples/coffee-roaster` (the same run as the README GIF and the landing page): the workspace tables after each stage (files, sources, profile, quality issues, entity links, metric definitions, facts, insights, decompositions, chunks, extracts, web results, quarantine, the verifier's check table), the planner's tool calls, the retrieval trace for the planner's own query, the sanitized web query and the fetcher's refusals;
  - the provider router on a scripted transport (no network, no keys): the call log of a rate-limited route handing over to a second provider, and a cached repeat;
  - the CLI's own output for each tutorial command (spawned `aa`, offline: scripted planner, hash embedder), with durations, job ids and temp paths normalised;
  - an in-memory MCP client against the same server `aa mcp` runs;
  - the security checks: the injection screen on the injection-suite fixtures, and `checkUrl` on the SSRF cases.
- `scripts/test/learn.test.ts`: regenerates and compares (floats to V2's tolerance), checks the run agrees with `pipeline.json`, every repo link exists, every `<Fact>` on a page is in that page's ledger.
- `scripts/test/site-commands.test.ts` also checks the commands stored in `learn.json`.

## Islands (few, reusable)

- `StageFlow`: in → stage → out, stepped through with buttons; each item can carry a figure and its fact chip. Final state server-rendered.
- `Transcript`: a recorded terminal session (command + output).
- `Fact` / `FactLedger` (Astro): a figure with its chip, linking to the page's fact ledger.
- `LearnMap`: the overview, every stage as a link with its real in/out counts.
- Reused: `RagStepper`, `VerifierDiff`, `Decomposition`, `CitationDemo`, `Mermaid`.

## Evals on your own data

`aa eval --suite real` reads only the public datasets' folders. Add `--answers <dir>` and `--data <dir>` (with `--results-dir`, defaulting to `./eval-results` when `--answers` is given), and accept answer files for datasets that aren't in the public list. Tests in evals/runner and the CLI; docs/EVALS.md and evals/real/README.md updated. A worked answer file for the example workbook lives in `examples/my-evals/`.

## Risks

- Test time: several engine runs. They run concurrently, in one test with a long timeout.
- Transcripts carry timings and temp paths: normalised in one place, and the page says so.
- A real model's output differs from the scripted planner's: every page says the example run is scripted (no LLM).
