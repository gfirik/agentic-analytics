# STATE: build ledger

This is the single source of truth for progress between agent sessions. Agents update it inside each milestone PR. Status values: `TODO` · `IN_PROGRESS` · `AWAITING_REVIEW` · `BLOCKED` · `DONE`.

Human gate values:
- `no`: merge and continue.
- `notify`: merge, continue, and message Firdavs to review when convenient.
- `yes`: stop at AWAITING_REVIEW until Firdavs approves. M12 was `yes` (launching is his call).

Since 2026-10-16 (maintainer's instruction, from PR #15 on): post the spec-reviewer and QA verdicts on the PR as a comment, put the real results in the description, then mark it ready and squash-merge when CI is green and both reviews pass, and notify. Making the repo public, enabling Pages, changing repo settings or pushing a `v*` release tag still need his explicit yes (pre-release `-rc` tags for testing are fine).

Since 2026-10-21 (maintainer's standing instruction): work through the whole plan without stopping (3D PR → code-quality review and fixes → M14 → M15 → M16 onwards). From then on every milestone's human gate is `notify`: merge when the gate, reviewer, QA and CI pass, then Telegram; rows before that date keep the gate they had. Where the plan asks the maintainer to review or decide something, the agent chooses the most spec-consistent option and records it under "Decisions made by agents". Still need the maintainer's explicit yes (noted under Blockers and skipped): a v* release tag or publishing a release, public announcements, repo settings and visibility, anything that costs money or needs their private credentials. A daily Telegram summary runs from the system crontab (`data/cron/daily-summary.sh`).
