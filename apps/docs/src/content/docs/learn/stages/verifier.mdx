**Stage 7 of 10.** `VERIFY` takes the draft report and checks it. Nothing reaches `report.json` without passing.

## The problem it solves

Language models are fluent, and fluent text is persuasive whether or not it is true. A model may cite a number that doesn't exist, say “caused by” when it only knows two things happened together, or recommend an action no finding supports. A careful human analyst catches those by re-checking. The verifier is that re-check, done by code, every time.

## The eight checks

| Check | Asks | If it fails |
|---|---|---|
| **V1** placeholders | Is every number in model text a `{{N…}}` placeholder for a fact that exists? | drop the claim |
| **V2** recompute | Run every fact's SQL or function again: same value (within 1e-9)? | **stop the job** |
| **V3** re-derive | Do headline totals match when computed another way (summing the members)? | **stop the job** |
| **V4** definitions | Does each fact match its metric's definition, period and filters, and the wording its sign? | drop |
| **V5** citations | Does each quote exist at its source, and do cited rows feed the fact? A judge model checks support. | drop |
| **V6** causal language | Do “caused”, “because”, “led to” have a document behind them? | reword or downgrade |
| **V7** grounding | Does each recommendation cite a surviving finding, with impact facts and a future check date? | drop the action |
| **V8** external | Does each web number cite its exact web source and stay labelled External? | drop |

Why do V2 and V3 stop the job instead of dropping a claim? Because a fact that doesn't recompute is not a model mistake, it is a bug in the engine. Shipping a report around it would hide the bug. The job fails with a diagnostics file instead.

## The ideas behind it

### Verify, don't trust

The model's text is treated as a draft from a junior colleague: useful, and checked line by line. The checks are cheap because every number is a fact with its computation attached; re-running it is one query.

### Causal grades

Saying *why* something happened is the riskiest thing an analyst does. Every claim carries a [causal grade](../../glossary/#causal-grade): `observed` (the numbers themselves), `correlated` (two things happened together), `document_supported` (a document says so, with a quote). V6 enforces the vocabulary: causal words need a document.

### Hallucination

When a model states something not supported by its input, that is called a [hallucination](../../glossary/#hallucination). You can't make a model stop; you can make sure nothing it states unsupported is shown to the reader as fact.
