**Stage 8 of 10.** `RENDER` writes `report.json` (the verified data) and `report.html` (a self-contained page you can open offline).

## The problem it solves

A report is only as useful as your ability to check it. “Revenue fell {factText(learn.analysis.change.pct).replace("−", "")}” in a slide is a claim; you would have to redo the work to trust it. Here every number sits next to a short ID, a [fact ID](../../glossary/#fact-id), and the ID opens the exact computation behind it: the SQL and its parameters, or the function and its inputs, down to the spreadsheet rows.

## The ideas behind it

### Provenance

[Provenance](../../glossary/#provenance) is the record of where something came from. Every fact has it (its computation and cited rows), every quote has it (file, page, character span), every web statement has it (URL and fetch time). A claim without provenance is not allowed in `report.json`.

### Placeholders, filled by code

The text in the report was written with `{{N12}}`-style placeholders. Rendering replaces each with the fact's stored value, formatted for reading: rounding happens only on screen, the stored value keeps full precision. That is why the report and `aa explain` always agree.

### One file you can keep

`report.html` carries its own data and script, makes no network requests, and works from a USB stick. `report.json` follows a published [schema](../../../reference/report-schema/), so other tools can read it.
