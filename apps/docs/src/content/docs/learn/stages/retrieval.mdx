## The problem it solves

The numbers say revenue fell in April and wholesale did it. They can't say *why*. The why is usually written somewhere: a price list, an email, a note. But you can't hand every document to a language model on every question (too long, too slow, and anything in them could steer it), and a plain keyword search misses passages that say the same thing in other words.

So the documents are cut into small passages called [chunks](../../glossary/#chunk), and a search picks the few that matter for one question. Only those are read, and only by the [quarantined extractor](../../glossary/#quarantined-extractor).

## The ideas behind it

### RAG

[Retrieval-augmented generation](../../glossary/#rag) means: before a model writes, find the few passages that are relevant and give it those, so it writes from evidence instead of memory. Here the model never sees raw passages at all; it sees the extractor's typed records.

### BM25: keyword search

[BM25](../../glossary/#bm25) scores a passage by the query words it contains, giving rare words more weight than common ones and not rewarding a long passage just for being long. It is exact and explainable, and it misses synonyms. The engine runs it inside DuckDB's full-text index, with stemming, so "increase" also matches "increases".

### Embeddings: meaning search

An [embedding](../../glossary/#embedding) is a list of numbers that places a text in a "meaning space", where texts about the same thing sit close together. The query is embedded too, and the nearest passages win, even if they share no words. The default model, `bge-m3`, runs in-process with no server; this page's run used <code>{r.embedder}</code>, an offline stand-in that hashes words, so tests and docs need no download.

### Reciprocal rank fusion

The two lists disagree. [RRF](../../glossary/#reciprocal-rank-fusion) combines them without comparing their scores (which are on different scales): each list gives a passage 1/(60 + rank) points, and points add up. A passage near the top of both lists beats one that tops only one. The email: 1/(60+{email?.bm25}) + 1/(60+{email?.vector}) = {email?.rrf.toFixed(4)}.

### Rerankers

A [reranker](../../glossary/#reranker) (a cross-encoder) reads the query and one passage *together* and scores how well the passage answers it. It is slower than both lanes, so it only reorders the top few. When it can't run, the engine says the result is degraded.
