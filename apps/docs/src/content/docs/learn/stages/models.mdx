## The problem it solves

The engine must run free: on a laptop with [Ollama](../../glossary/#ollama), or on the free tiers of hosted endpoints (Groq, Cerebras, OpenRouter and others that speak the OpenAI-compatible API). Free tiers have tight [rate limits](../../glossary/#rate-limit): a token budget per minute and a cap per day. A job makes dozens of calls. Without care, the third call fails with “429 Too Many Requests” and the job dies.

And when you compare results, you need to know which model on which endpoint answered each call.

## Roles

Three roles call a model, and each can use a different one:

- **planner** (`PLANNER_MODEL`): investigates and writes. The capable one.
- **extractor** (`EXTRACTOR_MODEL`): reads untrusted text and returns typed extracts. A small model is fine.
- **judge** (`JUDGE_MODEL`): answers yes or no: does this quote support this claim?

Embeddings run in-process (no model server at all).

## What happens: one call, two providers

The same open model, `gpt-oss-120b`, is served by more than one free provider. A role can list several routes for **the same model**, separated by `|`:

This record comes from the real model client on a scripted transport: the responses are canned, the code paths are the real ones, and nothing leaves the machine. (The keys in it are placeholders.)

Reading it top to bottom:

1. **Groq answered 429**, rate-limited, with a time to wait in its message. Rather than wait, the router handed the call to the next route of the same model.
2. **Cerebras answered**, but the first answer broke the schema (a grade that doesn't exist). The client fed the error back and asked again: the second answer was valid, <code>{JSON.stringify(rt.answer)}</code>.
3. **The same request again** was served from the response cache, both steps of the conversation, and the log says `cached`.

## The ideas behind it

### Routing without switching models

The router keeps a small budget per route, fed by the `x-ratelimit-*` headers each response carries and by 429s. A call goes to the first route with capacity. It never falls back to a *different* model: the config refuses routes that name different models, because a different model would make a different report, and results must say what produced them.

### Waiting politely

A 429 usually says how long to wait (the `Retry-After` header, or a “try again in …s” sentence in the body, like Groq's message in the log above). With no other route free, the client waits that long and retries, up to a cap. A wait longer than the cap fails clearly instead of hanging.

### The cache and the call log

Evals re-run the same prompts often. The cache stores complete answers keyed by a hash of the request, so a re-run costs nothing. The call log records which provider and model served every call, with token counts, so results are reproducible and attributable.

### Local first

Nothing requires a paid API. Ollama runs models on your machine; the hosted endpoints above have free tiers. Tests and these docs use no model at all.

## Try it

Check what is configured, per role, and that each endpoint answers:

```bash title="Terminal"
bun run aa doctor
```

With a free Groq key in `.env`, set `PLANNER_MODEL=openai-compatible:groq:openai/gpt-oss-120b` (and the other roles) and run the smoke evals:

```bash title="Terminal"
bun run eval -- --suite smoke --model configured --small-model
```
