# @agentic-analytics/cli

The `agentic-analytics` / `aa` command line (citty).

- **Status:** M0–M1 ship `aa doctor`; M4 adds `aa metrics`; M7 adds `aa run`; M10 adds `analyze`, `ask`, `explain`, `serve`, `mcp` and `jobs`. M11 adds `aa eval`; M14a adds `aa usage`.
- **Spec:** docs/specs/interfaces.md §2
- **Settings:** `aa` reads `.env` from the folder it runs in. A `.env` outside the repo is named on stderr (`aa: reading settings from "<path>"`); values are never printed (security.md §6).

## Commands

| Command | Does |
|---|---|
| `aa metrics <paths…> [--yes] [--save file] [--metrics file] [--currency CODE] [--today date]` | Ingest → profile → draft metric definitions (configured model, else deterministic fallbacks) → validate → interactive review (accept/edit/drop; `--yes` keeps drafts as assumptions) → print each metric in plain words with its SQL and recent values. `--save` writes the definitions for reuse with `--metrics`. |
| `aa run <paths…> [--dir folder] [--today date] [--currency CODE] [--objective text] [--small-model] [--web] [--embedder hash\|<model>] [--log]` · `aa run --resume <folder>` | A full job in a job folder (`input/`, `job.duckdb`, `metrics.drafted.json`, `report.draft.json`) with the configured models: ingest → profile → metrics (kept as assumptions) → measure/detect/decompose → index documents → explain → decide → draft. Prints each stage as it starts and ends. If a stage fails (e.g. no model reachable), the completed stages are kept and it prints the `--resume` command to continue. Small-model mode also turns on from the planner's model profile. It writes the verified `report.json` and `report.html`. |
| `aa analyze <paths…> [--yes] [--objective text] [--web] [--small-model] [--out dir] [--open] [--currency CODE] [--today date] [--embedder hash]` | A full job through the job manager (the API and MCP run jobs the same way). It shows a live stage view and, without `--yes`, an interactive metric review: accept, edit (YAML) or drop each metric. An edit the validator refuses is reported and reviewed again. The report is copied to `<out>/agentic-analytics/report.json` and `report.html`, and a summary is printed. |
| `aa ask <jobId> "question"` | A follow-up answer: verified claims with numbers from the report's facts, and how many statements failed verification. |
| `aa explain <jobId> <factId>` | The number, its label, definition, SQL and parameters (or function and inputs) and input rows. |
| `aa serve [--port 8080] [--host 127.0.0.1]` | The HTTP API, with the viewer at `/` and MCP at `/mcp`. `API_TOKEN` turns on bearer auth; a non-loopback `--host` needs it (or `--allow-no-auth` / `AA_ALLOW_NO_AUTH=1` behind a proxy or a 127.0.0.1 port mapping). `AA_MCP_ROOTS` lists the folders MCP over HTTP may read (none by default). |
| `aa mcp` | The MCP server on stdio (Claude Desktop config: apps/mcp/README.md). |
| `aa jobs ls \| rm <id> \| resume <id>` | Lists, deletes or resumes jobs in `AA_JOBS_DIR` (default `data/jobs`). |
| `aa eval [--suite smoke\|full] [--model baseline\|configured\|<provider:model>] [--small-model] [--embedder hash] [--keep-reports dir] [--replay-drafts dir] [--results-dir dir]` | Runs the eval suite on the generated datasets. `--keep-reports dir` keeps each report and each job's drafted metrics (`<dataset>.metrics.drafted.json`, also for a failed job). `--replay-drafts dir` (with `--model baseline`) answers each job's metric-draft request with the drafts kept there, so ranking is measured under a real model's metrics with no model call. It needs a `--results-dir` outside `evals/results` (a replay is never a published row). It writes `evals/results/*.json` and regenerates `evals/RESULTS.md` in a checkout; with `--results-dir dir` (and by default in the standalone binary, `./eval-results`) both go into that folder, and exits 1 if a bar fails (evals/runner/README.md). |
| `aa eval --suite smoke\|full [--label "<name>"] [--note "<text>"] [--only <id,…> --results-dir dir]` | `--label` names the run's model row in RESULTS.md and the README table, and its file (`<date>-<label slug>-<suite>.json`), e.g. `vllm (Kaggle 2×T4) Qwen3.8-27B-AWQ` for a self-hosted model. `--note` is shown above its table. `--only` runs some datasets of the suite (a chunk); it needs `--results-dir`, which can't be the checkout's `evals/results` or a folder inside it, and it must name at least one dataset, so a partial run never becomes a published row. Join the chunks into one row with `bun run eval:merge -- --label "<name>" <part.json>…` (evals/runner/README.md; used by evals/kaggle/full-suite-vllm.ipynb). |
| `aa eval --suite smoke\|full --models <a,b,c> [--small-model] [--keep-reports dir] [--note "<text>"]` | The model matrix: runs the suite once per model, one after another, each its own results row named by its model (provider routes or `baseline`; not `configured`). A model that fails is reported and the next runs; the command exits 1 when any model failed or missed a bar. `--keep-reports` keeps each model's reports in its own subfolder. Refuses `--model`, `--label`, `--passes`, `--replay-drafts` and `--suite real`. |
| `aa eval --suite smoke\|full --repeat <N> [--model m \| --models a,b] [--no-cache] [--only <id,…> --results-dir dir] [--keep-reports dir]` | Consistency: runs the suite N times (N ≥ 2) with the response cache off and prints the share of jobs where every run agrees on the numbers, the top-5 findings, each finding's top driver and cause grade, and the top action, against the launch bars. Writes `<results dir>/repeat/<date>-<model>-<suite>-repeat<N>.json` and the disagreements side by side in the `.md` beside it; no results row and no RESULTS.md change. `--keep-reports` keeps each run's reports in `dir/run-<k>/`. Exits 1 when a run left a job unfinished or a measure misses its bar. Refuses a count that isn't a whole number ≥ 2, `--passes` and `--suite real` (docs/specs/accuracy.md §7). |
| `aa eval … --no-cache` | No response cache: nothing is read from or written to `evals/.cache` (or `AA_MODEL_CACHE`), so every model call is live. Implied by `--repeat`. |
| `aa eval --suite smoke\|full --model configured --passes 2` | Carries a run over up to 2 passes (the nightly `scripts/eval-daily.sh`): the next day's pass resumes this row's latest result and runs only the jobs a free tier's quota stopped, then writes one combined result. A run is partial only when jobs are unfinished after its last pass. `--passes` takes a whole number ≥ 1 and doesn't go with `--only`. A `configured` run without `--label` is named after its routes (planner, extractor, judge); its file keeps the `configured` name (docs/EVALS.md §3–4). |
| `aa eval --suite real --answers <dir> [--data <dir>] [--model …] [--results-dir dir]` | The real-data checks on your own files: one answer file per dataset in `<dir>` (a dataset that isn't one of the public ones needs a `title`), the files they name in `--data` (default: the answers folder). With `--answers`, results and their RESULTS.md go to `./eval-results` unless `--results-dir` says otherwise, never to `evals/results`. Exits 1 if a check fails. |
| `aa usage [--day YYYY-MM-DD] [--log path] [--json]` | Without `--day`, first each route's tokens logged over the last 24 hours, with the provider's own count ("Used N of M", from its latest rate-limit error in that window): a provider counts its daily limit its own way, not per UTC day. `--json` carries it as `window` (absent with `--day`). Then tokens and calls per UTC day (newest first, or one `--day`), per role and per route, from the call log (default `data/logs/model-calls.jsonl`, only read). Each route's input + output tokens are shown against its free tier's daily limit from the route config (`daily_token_limits`, docs/specs/models.md §4), or "no known limit". Cached calls count 0 tokens; calls with no token count are listed as such. A missing log (`UsageError`, `NO_LOG`, `src/usage.ts`) or a `--day` that isn't YYYY-MM-DD (empty included) prints one line on stderr and exits 1. |
| `aa doctor` | Checks Node (≥22, required), DuckDB (required), Ollama, every configured OpenAI-compatible endpoint (keyed ones are probed), SearXNG and Docling; then calls the planner model with a one-line prompt if its provider is reachable. Prints a fix for each missing piece. Exits 1 only if a required check fails. |

`aa analyze`, `aa metrics` and `aa run` read folders the way the MCP door does (`src/collect.ts`, with `collectFiles` from `@agentic-analytics/mcp`): symlinks inside a folder are skipped, so a link back to a parent can't loop, and more than 500 files in all stop with `LimitError` (`TOO_MANY_FILES`). A path named on the command line is followed even when it is a symlink.

The metric review (`aa analyze` and `aa metrics` without `--yes`) reads its answers line by line from stdin, so answers piped in ahead of the questions are read in order; when the input runs out before every metric is answered, it stops with exit 1 and a message instead of asking again (`ReviewEndedError`, code `REVIEW_ENDED`, `src/prompt.ts`).

## Public API

`runDoctor(deps)`, `formatReport(results)`, `exitCode(results)` and their types are exported from `src/index.ts`. `fetch`, env and the DuckDB probe are injected, so tests never touch the network.

## Example

```bash
bun run aa doctor
```

## Standalone binary

`bun scripts/build-binary.ts` builds `dist/bin/aa-<os>-<arch>[.exe]` and its `.sha256` for the machine it runs on (`bun build --compile`); release tags build all four targets on native runners (`.github/workflows/binaries.yml`). DuckDB's addon needs its shared library, which the binary embeds and writes once to `<cache>/agentic-analytics/native/duckdb-<node-api version>-<platform>-<arch>/` before loading it (`src/native-lib.ts`). The binary sets `AA_STANDALONE=1`, and `src/standalone.ts` holds what that changes: the hash embedder by default (no ONNX), no viewer at `/`, `aa eval` results in `./eval-results`, and doctor naming the Bun runtime. See docs/DECISIONS.md D16.
